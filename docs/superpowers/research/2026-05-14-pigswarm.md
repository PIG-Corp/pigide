# PigSwarm — implementation plan

**Date:** 2026-05-14
**Source:** subagent research
**Status:** plan only. Зависит от Tasks (миграция 3-4) и Memory.

## 1. Roles

**DDL (migration 5):**
```sql
ALTER TABLE agents ADD COLUMN role TEXT NOT NULL DEFAULT 'builder'
  CHECK(role IN ('coordinator','builder','reviewer','scout'));
CREATE INDEX idx_agents_role ON agents(role);
```

`src-tauri/src/swarm/role.rs` с enum `Role` + `default_prompt(role)`. `settings.roles.<name>.prompt` overrides. Промпт инжектится в PTY первой строкой после prompt-detect (regex `> ` / `❯ `, задержка 200 мс).

Назначение только при spawn: `spawn(workspace, agent_type, role, cwd)`. Смена роли = kill+respawn.

**Риск:** Kiro CLI без `--system` — митигация через первое stdin сообщение с задержкой.

## 2. Mailbox

```sql
CREATE TABLE mailbox (
  id            TEXT PRIMARY KEY,
  from_agent_id TEXT REFERENCES agents(id) ON DELETE SET NULL,
  to_addr       TEXT NOT NULL,        -- agent UUID или 'role:builder'
  body          TEXT NOT NULL,
  thread_id     TEXT,
  created_at    TEXT NOT NULL,
  read_at       TEXT
);
CREATE INDEX idx_mbox_to_unread ON mailbox(to_addr, read_at);
CREATE INDEX idx_mbox_thread ON mailbox(thread_id);
```

Tools: `send_mail`, `read_mailbox`, `mark_read`, `broadcast(role)`.

**Доставка — гибрид «inbox-poke».** Сервер пушит в PTY одну строку: `\n[mailbox] 1 new message — call read_mailbox\n`. Только если агент idle >2 с (нет stdout-bytes). `tokio::sync::Notify` per agent.

## 3. File ownership

```sql
CREATE TABLE file_locks (
  path        TEXT NOT NULL,
  task_id     TEXT NOT NULL REFERENCES tasks(id) ON DELETE CASCADE,
  agent_id    TEXT NOT NULL REFERENCES agents(id) ON DELETE CASCADE,
  locked_at   TEXT NOT NULL,
  expires_at  TEXT NOT NULL,
  PRIMARY KEY(path)
);
CREATE INDEX idx_locks_task ON file_locks(task_id);
```

Path normalize через `dunce::canonicalize`. TTL 30 мин default.

**Стратегия: soft + hard для tool-mediated writes.**
- Soft: `notify`-watcher эмитит warning в mailbox + frontend toast.
- Hard: для будущего `write_file`-tool — pre-check.
- Для прямых правок CLI-агента — soft, эскалация в Coordinator-mailbox после 3 нарушений.

## 4. Quality gates

```sql
CREATE TABLE reviews (
  id                TEXT PRIMARY KEY,
  task_id           TEXT NOT NULL REFERENCES tasks(id) ON DELETE CASCADE,
  reviewer_agent_id TEXT REFERENCES agents(id) ON DELETE SET NULL,
  verdict           TEXT NOT NULL CHECK(verdict IN ('pass','fail','pending')),
  comment           TEXT,
  diff_sha          TEXT,
  created_at        TEXT NOT NULL
);
```

Интерсептор `update_task(status=complete)`:
1. `git diff <task.base_ref>..HEAD` через git2 либо Command.
2. INSERT review verdict='pending'.
3. Spawn ephemeral Reviewer (default Claude).
4. Парсер stdout regex `^verdict:\s*(PASS|FAIL)`.
5. Timeout 5 мин → fail with `comment='timeout'`.
6. PASS → `tasks.status='complete'`.

## 5. Auto-эскалация

`AgentManager.last_stdout_at: HashMap<agent_id, Instant>`, обновлять в reader-thread. Background `tokio::task` с `interval(30s)`. Если silence > `settings.swarm.silence_timeout_secs` (default 300) → INSERT mailbox to coordinator.

## 6. Live indicators

Расширить enum: `running, idle, busy, handoff_ready, complete, exited`. Эмитить `EV_AGENT_STATUS`. `tauri-plugin-notification` на `complete`. Detection idle/busy по `last_stdout_at < 2 s back`.

## 7. Side chat

**Не отдельная таблица.** `mailbox` rows с непустым `thread_id`. Tool `open_thread(other_agent_id)` возвращает или создаёт `thread_id`.

## 8. Roll-call

```sql
CREATE TABLE rollcall_responses (
  rollcall_id TEXT NOT NULL,
  agent_id    TEXT NOT NULL,
  body        TEXT NOT NULL,
  created_at  TEXT NOT NULL,
  PRIMARY KEY(rollcall_id, agent_id)
);
```

Split: `start_rollcall(role, prompt, timeout_secs?)` → returns id; `respond_rollcall({rollcall_id, body})`; `collect_rollcall(id)` через N сек агрегирует.

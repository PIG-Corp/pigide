# PigIDE — что ещё нужно доделать, чтобы выпустить релиз

> Простыми словами, без технического жаргона. Тут список того, что **стоит починить до того, как программой начнут пользоваться обычные люди**, а не разработчики.
>
> **Приоритеты:**
> - 🔴 **Критично** — без этого нельзя выпускать вообще
> - 🟠 **Важно** — нужно сделать до публичного запуска
> - 🟡 **Желательно** — первые пару месяцев после запуска
> - 🟢 **Когда-нибудь** — долгосрочный список
>
> **Время:** ⏱ = пару часов, ⏱⏱ = день-два, ⏱⏱⏱ = неделя

---

## TL;DR — коротко о главном

PigIDE — мощная штука: тайлинг терминалов, голос, MCP, swarm агентов, навыки, вот это всё. Но чтобы это мог поставить себе обычный человек и не получить сюрприз — нужно закрыть несколько дыр.

Главные проблемы сейчас:

1. **Безопасность.** В программе есть «чёрные ходы», через которые вредоносный код на странице может натворить дел (стереть данные, получить доступ к секретам, запустить агента где не надо).
2. **Автообновления.** Они есть, но без подписи — а это значит, что если кто-то перехватит соединение, он может подсунуть свою версию программы.
3. **Установка на Windows и Mac.** Без подписи кода Windows будет ругаться красным экраном, macOS — GateKeeper-предупреждением.
4. **Краш-репорты.** Если у пользователя что-то падает, мы об этом не узнаем. Нет телеметрии, нет Sentry.
5. **Документация для пользователя.** README огромный, но нет ни раздела «у меня не работает голос, что делать?», ни встроенной справки.

Дальше — подробно.

## 🔴 Критично — без этого не выпускаем

### 1. Все «кнопки» программы доступны веб-странице без ограничений

**Что это значит:** PigIDE внутри — это окно с веб-страницей (React). У этой страницы есть доступ ко всем 128 «кнопкам» программы (создать агента, удалить workspace, дать MCP-ключ, etc.). Если в React-коде или в одной из npm-зависимостей когда-нибудь появится XSS-уязвимость (а они регулярно появляются в npm-мире) — эта дырка автоматически получит доступ ко всему.

**Что делать:** составить точный список «какие кнопки веб-страница может нажимать», и в нём перечислить только нужные. Сейчас в нём либо всё, либо ничего — это нужно исправить.

**Зачем простому пользователю:** чтобы баг в условном `react-pdf` не превращался в «удалили все ваши проекты».

**Где:** `capabilities/default.json`.

⏱⏱

---

### 2. Агента можно запустить в любой папке компьютера

**Что это значит:** Когда пользователь создаёт агента (Claude, Kiro), он может указать, в какой папке тот будет работать. Сейчас эта папка никак не проверяется — можно написать `/etc`, и агент запустится в системной папке, откуда сможет прочитать любые конфиги и секреты.

**Что делать:** проверять, что папка находится внутри одного из «разрешённых» рабочих пространств (workspace). Если не в нём — отказывать.

**Зачем простому пользователю:** защита от случайной ошибки и от вредоносного кода.

**Где:** код, который запускает агентов.

⏱⏱

---

### 3. Автообновления не подписаны

**Что это значит:** PigIDE умеет обновляться сам. Но сейчас он принимает обновление «на слово» — без криптографической подписи. Если кто-то перехватит трафик (в кафешке, в аэропорту, через вредоносный роутер), он может подсунуть свою версию программы, и она установится как обычное обновление.

**Что делать:** сгенерировать криптографический ключ, положить его публичную часть в конфиг, а приватной подписывать обновления. Проверка подписи — одна строка в коде.

**Зачем простому пользователю:** чтобы не подхватить троян через «обновление PigIDE».

**Где:** `tauri.conf.json`, секция updater.

⏱

## 🟠 Важно — нужно до запуска

### Безопасность

#### 4. Ссылки `pigide://...` могут запустить агента где угодно
**Что это значит:** Если кто-то откроет в браузере ссылку вида `pigide://запустить-агента?папка=/etc`, PigIDE молча выполнит. Это удобно для интеграций, но опасно — любой сайт может попробовать такую ссылку.

**Что делать:** проверять папку и рабочее пространство перед запуском, как в пункте 2.

⏱

#### 5. Сетевой доступ к MCP — «включил и забыл»
**Что это значит:** MCP (это протокол, через который PigIDE общается с другими программами) можно сделать доступным со всей локальной сети. Включил — и любой в твоей Wi-Fi сети может управлять твоими агентами.

**Что делать:** требовать подтверждения пользователя (диалог «Точно хочешь открыть доступ в сеть?»), не разрешать включать программно.

⏱

#### 6. Ключ MCP с полными правами создаётся одним кликом
**Что это значит:** Любая веб-страница в PigIDE может создать себе ключ, который умеет удалять workspace'ы и запускать агентов. Это сделано для удобства, но в случае XSS это превращается в «ключ от всего».

**Что делать:** добавить запрос «Точно?» с вводом пароля, либо убрать «полный» уровень прав, оставить только «чтение» и «умеренные действия» по умолчанию.

⏱

#### 7. Любая веб-страница может заблокировать тебя из MCP
**Что это значит:** Кнопка «удалить MCP-ключ» доступна без подтверждения. XSS → удалили все ключи → ты не можешь пользоваться MCP, даже после перезагрузки.

**Что делать:** требовать подтверждения для удаления ключей.

⏱

#### 8. Провайдер LLM может быть подменён на вредоносный
**Что это значит:** Программа позволяет настроить, к какому LLM-провайдеру ходить (Anthropic, OpenRouter, свой). Но «свой» — это любая ссылка, хоть `http://хакер.com/v1/chat». Если такое настроить случайно или через XSS — все промпты утекут.

**Что делать:** белый список «надёжных» провайдеров, для кастомных — обязательное подтверждение.

⏱

#### 9. Токен MCP для агентов хранится открытым текстом
**Что это значит:** В базе данных программы (SQLite) лежат API-ключи. Часть из них зашифрована, а часть — нет. В частности, токен, который Claude-агент использует для доступа к MCP, лежит в открытом виде.

**Что делать:** зашифровать его, как остальные секреты.

⏱⏱

#### 10. Логи терминалов читаются любым пользователем компьютера
**Что это значит:** Программа сохраняет полный вывод всех агентов в файлы на диске. Если на компьютере несколько пользователей (например, семейный ноутбук), второй пользователь может открыть эти файлы и прочитать всё, что ты делал — включая введённые пароли и API-ключи.

**Что делать:** запретить чтение этих файлов для всех, кроме владельца (chmod 600 / правильные права на Windows).

⏱

#### 11. Защита секретов «обходится» в обход основного пути
**Что это значит:** Есть защита — программа не даёт веб-странице менять «какой именно бинарь запускается» (например, заменить `claude` на `curl-хакер.com/x`). Но эта защита стоит в одном конкретном месте, а есть другие места в коде, через которые можно добраться до того же самого. Защита обходится, если кто-то знает, куда смотреть.

**Что делать:** переместить защиту в самое «нижнее» место — в код, который пишет в базу. Тогда все пути будут защищены.

⏱

#### 12. Нет лимита на размер текста в чате и вводе в терминал
**Что это значит:** Можно отправить агенту 10 мегабайт текста одним сообщением, и программа будет его обрабатывать, тормозя всё. Злоумышленник может «положить» программу таким способом.

**Что делать:** поставить разумные лимиты (64 КБ на ввод в терминал, 1 МБ на сообщение, 20 файлов-вложений).

⏱

### Производительность

#### 13-16. Тяжёлые операции блокируют интерфейс
**Что это значит:** Когда ты нажимаешь кнопку и программа «замирает на 3 секунды» — это обычно значит, что какая-то тяжёлая штука (чтение большого файла, обход папки, обращение к базе) выполняется в «главном потоке», и пока она не закончится, интерфейс не отвечает.

**Что делать:** вынести тяжёлые операции в фоновые потоки. В программе есть 10+ таких мест — крупные чтения файлов, обход папок до 2000 файлов, пересборка индекса проектов.

**Зачем простому пользователю:** интерфейс не зависает, можно работать, пока что-то считается в фоне.

⏱⏱⏱ (10 мест, каждое по ⏱⏱)

### Наблюдаемость

#### 17. Нет уведомлений о сбоях
**Что это значит:** Если у пользователя программа вылетела с ошибкой — мы об этом не узнаем. У пользователя тоже нет удобного способа отправить отчёт.

**Что делать:** подключить Sentry (или аналог). Опционально, с явного согласия пользователя.

**Зачем простому пользователю:** баги, которые ты заметил, действительно попадут к разработчикам, а не останутся «где-то в воздухе».

⏱⏱⏱

#### 18. Нет метрик скорости
**Что это значит:** Программа знает, сколько времени занимает каждый шаг (распознавание голоса, ответ LLM, запуск агента), но не показывает это нигде. Когда что-то «тормозит» — непонятно, где именно.

**Что делать:** добавить хотя бы простой лог последних N событий с таймингами. Опционально — `Settings → Diagnostics` с графиками.

⏱⏱

#### 19-20. Мелочи в логах и обработке ошибок
**Что это значит:**
- В коде 42 места, где программа «упадёт с паникой» в случае неожиданных данных. Часть из них — в путях, которые почти не сработают, но всё-таки могут.
- Лог-фильтр в коде настроен криво (второй параметр не имеет смысла).

**Что делать:** заменить «упасть с паникой» на «вернуть ошибку», поправить лог-фильтр.

⏱⏱

### Установка и распространение

#### 21-23. CSP — слишком разрешительный
**Что это значит:** CSP (Content Security Policy) — это «белый список», кому веб-страница внутри PigIDE может делать запросы. Сейчас там написано «можно всем по HTTP и HTTPS» — это слишком щедро. Если в React-коде заведётся XSS, он сможет стучаться на любой сайт мира.

**Что делать:** оставить только `localhost` (для локального MCP-сервера) и убрать «любой HTTPS».

⏱

#### 24. Windows: нет цифровой подписи
**Что это значит:** Windows SmartScreen при установке будет показывать «Этот файл от неизвестного издателя, вы уверены?» — и 80% пользователей просто закроют установку.

**Что делать:** купить сертификат подписи кода (для разработчика — расход), настроить автоматическую подпись в скрипте сборки.

⏱⏱⏱

#### 25. macOS: нет нотаризации
**Что это значит:** То же самое для macOS — Apple GateKeeper будет ругаться.

**Что делать:** Apple Developer ID ($99/год), настроить `notarytool`.

⏱⏱⏱

#### 26. Linux: нет файла `.desktop` для `pigide://` ссылок
**Что это значит:** Программа регистрирует себя как обработчик ссылок `pigide://...`, но в Linux для этого нужен специальный файл `.desktop`, который не создаётся при установке. Ссылки работать не будут.

**Что делать:** положить `.desktop` в пакет, проверить установку.

⏱

#### 27. Нет SBOM (списка всех библиотек)
**Что это значит:** SBOM — это «список ингредиентов» программы (все используемые библиотеки и их версии). Без него в случае находки критической уязвимости в какой-нибудь библиотеке непонятно, какие версии PigIDE затронуты.

**Что делать:** генерировать SBOM при каждом релизе, публиковать рядом с бинарниками.

⏱⏱

### CI/CD (автоматизация проверок и сборки)

#### 28. CI не запускает E2E-тесты
**Что это значит:** E2E (end-to-end) тесты — это «бот открывает программу, жмёт кнопки, проверяет результат». У нас есть такие тесты, но они не запускаются автоматически перед каждым изменением. Можно нечаянно сломать кнопку и узнать об этом через неделю от пользователя.

**Что делать:** добавить запуск Playwright-тестов в CI.

⏱⏱

#### 29. CI не подписывает артефакты сборки
**Что это значит:** Бинарники не подписываются криптографически. Связано с пунктом 3 (updater) и пунктами 24-25 (Windows/macOS).

⏱⏱⏱

### Документация

#### 30. Нет `SECURITY.md`
**Что это значит:** Если исследователь безопасности найдёт дыру — непонятно, кому писать. Сейчас нет ни email'а, ни Discord'а, ни сроков ответа.

**Что делать:** добавить `SECURITY.md` (поддерживаемые версии, куда писать, как быстро отвечаем).

⏱

#### 31. Нет `CHANGELOG.md`
**Что это значит:** Нет списка «что изменилось в версии 0.5». Пользователь не знает, что нового, и разработчик не может быстро посмотреть «что мы там чинили в прошлом релизе».

**Что делать:** генерировать из conventional commits автоматически (через `release-please` или `git-cliff`).

⏱⏱

### Тесты

#### 32. Нет юнит-тестов на React-компоненты
**Что это значит:** Есть тесты на маленькие утилиты (5% кода), но не на сами компоненты — окно чата, панель памяти, список workspace'ов. Если кто-то рефакторит код — никто не узнает, что сломал кнопку.

**Что делать:** Vitest + Testing Library, покрыть критические компоненты тестами.

⏱⏱⏱

#### 33. «Восстановление сессии» не покрыто тестами
**Что это значит:** Когда PigIDE вылетает и перезапускается, он восстанавливает запущенных агентов. Это сложная и важная функция, но нет автоматического теста «а точно восстановится?».

**Что делать:** добавить интеграционный тест.

⏱⏱

#### 34. Нет тестов для xterm-интеграции
**Что это значит:** Терминал внутри PigIDE (xterm) — отдельная сложная штука. Если что-то сломается в передаче ввода/вывода, заметим не сразу.

⏱⏱

## 🟡 Желательно — первые месяцы после запуска

### Безопасность (мелочи)

#### 35-43. Десяток мелких валидаций
- «Удалить проект» не проверяет путь → проверять.
- Создание пользовательского навыка не проверяет имя файла → проверять (имя не должно содержать `..`).
- Импорт навыков Claude ходит по путям, которые указал пользователь → добавить подтверждение.
- «Включить Architect» без подтверждения → добавить.
- Списки файлов (claim/release) без лимита на длину → добавить cap.
- WSL-обёртка принимает любое имя дистрибутива → проверять regex'ом.
- Парсинг аргументов командной строки ломается на кавычках → использовать нормальный парсер.
- Главный ключ шифрования на Windows без явных прав → добавить.
- CSP разрешает фреймить любой сайт → убрать.
- Используется переменная окружения `$UID` вместо реального `getuid()` → починить.
- Очистка старого сокета идёт по симлинкам → проверять.

Каждое ⏱, итого ⏱⏱⏱.

### Производительность

#### 44-51. Sync-операции в async-путях
**Что это значит:** Программа написана на языке, где есть «главный поток» (отвечает за интерфейс) и фоновые потоки. Часть тяжёлой работы случайно оказалась в главном потоке. Около 10 мест.

⏱⏱⏱

### Наблюдаемость

#### 52. Логи не ротируются
**Что это значит:** Если оставить программу включённой на неделю, лог-файл вырастет до гигабайт.

**Что делать:** настроить ротацию (1 файл в день, максимум 50 МБ).

⏱

#### 53. Не логируются действия пользователя
**Что это значит:** Когда пользователь пишет «у меня ничего не работает», мы не можем посмотреть «а что он делал до этого». Без слежки, естественно — только анонимная статистика «открыл workspace, запустил агента».

⏱⏱

### UX

#### 54. ErrorBoundary молчит
**Что это значит:** Если у пользователя упал какой-то блок интерфейса (например, панель памяти), он видит «Произошла ошибка. Повторить?» — но не может отправить отчёт разработчикам.

**Что делать:** кнопка «Сообщить об ошибке» — открывает GitHub issue с предзаполненным текстом.

⏱⏱

#### 55. Нет индикатора загрузки для долгих операций
**Что это значит:** «Перестроить индекс проектов» может идти минуту. Сейчас непонятно, идёт ли вообще что-то.

⏱⏱

#### 56. В README смешаны русский и английский
**Что это значит:** Заходит англоязычный пользователь, видит стену русского текста, уходит.

**Что делать:** вынести русский в отдельный файл, основной README сделать на английском.

#### 59. Нет встроенной справки / онбординга
**Что это значит:** Новый пользователь открывает программу, видит пустой workspace, не понимает, что делать.

### Тесты

#### 61-64. Больше тестов
